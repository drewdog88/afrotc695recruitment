# AFROTC 695 Recruitment Management System - 2FA Feature PRD

## Product Overview
Implement optional Two-Factor Authentication (2FA) for the AFROTC 695 Recruitment Management System to enhance security while maintaining usability for existing users.

## Problem Statement
The current system uses only username/password authentication. While functional, it lacks the security benefits of multi-factor authentication that could protect sensitive PII (Personally Identifiable Information) of cadets and recruits.

## Goals
- Add optional 2FA without breaking existing password-based authentication
- Enhance security for users who choose to enable 2FA
- Maintain backward compatibility for all existing users
- Provide multiple recovery options (backup codes)
- Ensure Vercel deployment compatibility

## Success Metrics
- Zero disruption to existing user login workflows
- 100% backward compatibility maintained
- Users can optionally enable/disable 2FA
- Successful deployment to Vercel with all 2FA features working
- Comprehensive backup and recovery mechanisms

## Technical Requirements

### Core Technology Stack
- **Framework**: Flask (existing)
- **Database**: Neon PostgreSQL (both local and production) - existing
- **Deployment**: Vercel (existing)
- **2FA Method**: TOTP (Time-based One-Time Passwords) using authenticator apps
- **Encryption**: Fernet (cryptography library) for TOTP secret storage
- **QR Code Generation**: qrcode library for easy 2FA setup

### Database Schema Changes
Add the following optional columns to the User table:
- `totp_secret` (VARCHAR(255)) - Encrypted TOTP secret
- `totp_enabled` (BOOLEAN) - Whether 2FA is enabled for user
- `backup_codes_hash` (TEXT) - JSON array of bcrypt-hashed backup codes
- `totp_setup_completed` (BOOLEAN) - Whether 2FA setup is complete

### Security Requirements
- TOTP secrets must be encrypted before database storage
- Backup codes must be bcrypt-hashed
- Rate limiting on 2FA verification attempts
- Session management for 2FA verification flow
- Secure QR code generation for authenticator app setup

### User Experience Requirements
- Existing users continue to login normally without any changes
- 2FA setup is completely optional and user-initiated
- QR code display for easy authenticator app setup
- Backup codes provided during 2FA setup for account recovery
- Clear error messages for invalid codes
- Ability to disable 2FA if needed

## Feature Components

### 1. Database Migration
- Create migration script to add new columns to Neon PostgreSQL
- Ensure existing data integrity
- Test migration on the shared Neon PostgreSQL database

### 2. Core 2FA Utility Functions
- `encrypt_totp_secret()` - Encrypt TOTP secrets
- `decrypt_totp_secret()` - Decrypt TOTP secrets
- `generate_backup_codes()` - Generate recovery codes
- `hash_backup_code()` - Hash backup codes for storage
- `verify_backup_code()` - Verify backup codes during recovery

### 3. New Routes and Endpoints
- `/setup-2fa` - 2FA setup and configuration
- `/verify-2fa` - 2FA verification during login
- `/manage-2fa` - Enable/disable 2FA in user profile
- `/regenerate-backup-codes` - Generate new backup codes

### 4. User Interface Components
- 2FA setup page with QR code display
- 2FA verification page during login
- 2FA management in user profile
- Backup code display and regeneration interface

### 5. Authentication Flow Modifications
- Modified login route to check for 2FA requirement
- Session management for 2FA verification state
- Integration with existing password authentication

### 6. Template Files
- `setup_2fa.html` - QR code and verification form
- `verify_2fa.html` - 2FA code input during login
- `manage_2fa.html` - 2FA management interface
- Updated `profile.html` - Add 2FA management section

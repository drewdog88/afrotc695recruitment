# Task ID: 12
# Title: Migrate Application Database from SQLite to Neon PostgreSQL
# Status: done
# Dependencies: 2, 11
# Priority: high
# Description: Transition the application's database from SQLite to Neon PostgreSQL, including database creation, connection string configuration, codebase updates, and data migration.
# Details:
1. Provision a Neon PostgreSQL database instance using the Neon dashboard, taking advantage of serverless scaling and branching features for safe migration and testing.
2. Generate secure credentials for the Neon database and store them as environment variables in the deployment platform (e.g., Vercel dashboard).
3. Update the application's configuration files and ORM/database libraries to use the Neon PostgreSQL connection string instead of SQLite, ensuring all database access references the new environment variables.
4. Refactor any application code that relies on SQLite-specific features (e.g., dynamic typing, lack of array or JSON support) to use PostgreSQL equivalents, such as native JSON and array types, window functions, and materialized views.
5. Select and configure a migration tool (such as Alembic, Django migrate, or custom ETL scripts) to transfer all schema and data from SQLite to Neon PostgreSQL, addressing type differences and ensuring data integrity.
6. Validate the migrated schema and data, checking for consistency, completeness, and compatibility with PostgreSQL features.
7. Optimize database indexes and queries for PostgreSQL performance and scalability, leveraging advanced features as needed.

# Test Strategy:
- Attempt to connect to the Neon PostgreSQL database from the application using the configured connection string and environment variables.
- Run the application and verify that all database-driven features function correctly, including CRUD operations, complex queries, and JSON/array handling.
- Compare row counts and sample data between the old SQLite database and the new Neon PostgreSQL instance to ensure data integrity.
- Execute performance benchmarks on key queries and workflows to confirm improved scalability and responsiveness.
- Monitor for errors or incompatibilities related to data types, query syntax, or feature support, and resolve any issues found.
